# Architecture, Versions and Deployment Plan

Heart-disease risk classifier (UCI Cleveland data) packaged as a Flask API with a Streamlit UI, monitored with Prometheus, Loki and Grafana, and deployed to a single VPS with Docker Compose.

Status legend: **Done** = in the repo and verified, **Planned** = not built yet.

---

## 1. System overview

```
                          ┌────────────────────────────── VPS (Docker host) ──────────────────────────────┐
                          │                                                                               │
  Browser ── HTTPS ──►  Reverse proxy (Planned)                                                           │
                          │   ├── /            ─► ui         Streamlit        :8501  (host 7202)          │
                          │   ├── /api/        ─► api        Flask + gunicorn :8000  (host 7201)          │
                          │   └── /grafana/    ─► grafana    Grafana          :3000  (host 7205)          │
                          │                                                                               │
                          │   ui ──POST /predict──► api ──► heart_model.joblib (baked into image)         │
                          │                                                                               │
                          │   prometheus (:9090, host 7203) ──scrape /metrics every 5s──► api             │
                          │   promtail ──reads container logs via docker.sock──► loki (:3100, host 7204)  │
                          │   grafana ──queries──► prometheus + loki                                      │
                          └───────────────────────────────────────────────────────────────────────────────┘

  Offline / CI:  data ─► src/ (clean, features, train) ─► MLflow (sqlite) ─► models/heart_model.joblib
```

All services run on one Compose network (`mlops-assignment-1_default`) and reach each other by service name (`api`, `loki`, `prometheus`).

## 2. Single source of truth

All ML logic lives in `src/`. Nothing is duplicated.

| Consumer | How it uses `src/` |
|---|---|
| `assignment.ipynb` | `from src import data, features, train` |
| `tests/` | imports and exercises the same modules |
| `api/app.py` | imports `src.config` (feature list, labels); the pickle needs `src.features.FeatureEngineer` to unpickle |
| CI | runs `python -m src.train` and pytest against `src/` |

## 3. Components

### 3.1 ML pipeline (`src/`) — Done
| File | Role |
|---|---|
| `config.py` | paths, column groups, seeds, MLflow settings |
| `data.py` | download from UCI, clean, write `data/processed/heart_clean.csv` |
| `features.py` | `FeatureEngineer` (adds `hr_pct_max`, `oldpeak_x_exang`) and the sklearn `Pipeline`: engineer, impute/scale/one-hot, `SelectKBest`, classifier |
| `train.py` | hyper-parameter search, nested CV, MLflow tracking, model selection, packaging |

- Candidates: logistic regression, random forest, gradient boosting. Winner: **logistic regression** (nested-CV ROC-AUC 0.891, test ROC-AUC 0.951, test recall 0.929).
- The whole preprocessing chain is inside the pickled pipeline, so serving needs no separate transformers.
- Seed `42`, test split `0.20`.

### 3.2 Experiment tracking — Done
- MLflow with a SQLite backend (`mlflow.db`) and file artifacts (`mlartifacts/`). Both are git-ignored and regenerated by `python -m src.train`.
- Experiment `heart-disease-risk`, registered model `heart-disease-classifier`.
- Logged per run: params, CV and test metrics, ROC / confusion-matrix / feature-importance plots.
- The MLflow UI is **not** in Compose; run it locally with `mlflow ui --backend-store-uri sqlite:///mlflow.db`.

### 3.3 Backend API (`api/`) — Done
- Flask app served by gunicorn (1 worker, 4 threads, so in-memory Prometheus counters stay correct).
- Endpoints:

| Method | Path | Purpose |
|---|---|---|
| GET | `/health` | liveness (used by the Docker healthcheck) |
| GET | `/` | service info and required feature list |
| POST | `/predict` | 13 numeric features in, `prediction`, `label`, `confidence`, `probability_disease` out; 400 on missing or non-numeric input |
| GET | `/metrics` | Prometheus exposition |

- Model and `src/` are copied into the image, so the container is self-contained.
- Runs as a non-root user.

### 3.4 Frontend (`ui/`) — Done
- Streamlit form with labelled dropdowns; calls `POST ${API_URL}/predict` (`API_URL=http://api:8000` in Compose).
- Shows label, confidence, disease probability and the raw request/response.

### 3.5 Logging and monitoring (`monitoring/`) — Done
| Concern | Tool | Detail |
|---|---|---|
| Structured logs | API → stdout | one JSON object per line: `request`, `prediction`, `invalid_request`, `model_loaded` |
| Log shipping | Promtail | Docker service discovery, filtered to the Compose project; promotes `event` to a label |
| Log storage | Loki (filesystem, TSDB schema v13) | volume `loki-data` |
| Metrics | Prometheus | scrapes `api:8000/metrics` every 5s; volume `prometheus-data` |
| Dashboards | Grafana | datasources and the "Heart Disease API" dashboard are provisioned from files |

API metrics: `api_requests_total{method,endpoint,status}`, `api_request_latency_seconds`, `api_predictions_total{label}`, `api_prediction_confidence`, `api_invalid_requests_total`.

### 3.6 CI (`.github/workflows/mlops-ci.yml`) — Done
Triggers: pull requests into `main`, and manual dispatch.

`lint (flake8 src tests)` → `test (pytest)` → `train + quality gate` (retrains, then asserts ROC-AUC ≥ 0.85 and recall ≥ 0.80). Uploads the lint log, JUnit report, training log, models and MLflow store.

Known gaps (Planned): CI does not lint `api/` and `ui/`, and does not build the Docker images.

## 6. VPS deployment plan

Target: one Linux VPS (Ubuntu LTS), everything under Docker Compose. Sizing: 2 vCPU / 4 GB RAM is enough; Loki, Prometheus and Grafana are the main memory users.

### Phase 1: Prepare the host
1. Create a non-root sudo user, disable password SSH login, use key auth.
2. Install Docker Engine and the Compose plugin; add the user to the `docker` group.
3. Firewall (ufw): allow `22`, `80`, `443` only. Ports 7201–7205 stay closed to the internet.
4. Point a DNS name at the VPS.

### Phase 2: Ship the code and run
1. `git clone` the repo on the VPS (`models/heart_model.joblib` is committed, so no training is needed on the server).
2. `docker compose up -d --build`.
3. Smoke test from the VPS: `curl localhost:7201/health`, then a sample `/predict`.

### Phase 3: Public access and hardening (required before going live)
1. **Reverse proxy with TLS**: Caddy or nginx on 80/443 (automatic Let's Encrypt with Caddy). Route `/` to the UI, `/api/` to the API and `/grafana/` to Grafana.
2. **Bind internal ports to localhost**: change mappings to `127.0.0.1:7203:9090` and `127.0.0.1:7204:3100`; do the same for api/ui/grafana once the proxy fronts them. Reach Prometheus/Loki via SSH tunnel.
3. **Grafana credentials**: remove the hard-coded `admin/admin` and anonymous access. Read the admin password from a `.env` file that is not committed, and set `GF_SERVER_ROOT_URL` / sub-path settings for the proxy.
4. **Secrets**: keep `.env` out of git; add `.env.example`.
5. **Docker socket**: Promtail mounts `/var/run/docker.sock` read-only, which still grants broad visibility. Acceptable on a single-purpose VPS; the alternative is the Docker `loki` logging driver.
6. **Input privacy**: the API logs prediction inputs. Health data is sensitive, so drop or hash inputs from logs before real patient data is used.
7. Basic rate limiting on `/predict` at the proxy.

### Phase 4: Persistence and operations
- Named volumes already persist Prometheus, Loki and Grafana data. Back them up (`docker run --rm -v ...` tar to off-host storage) on a schedule.
- Set Loki and Prometheus retention (e.g. 15 days) to bound disk use.
- Add `restart: unless-stopped` (already set) and a `healthcheck` for the UI.
- Log rotation: configure `max-size` / `max-file` for the Docker `json-file` driver.

### Phase 5: Automated deploy (CD)
1. Build and push `heart-api` and `heart-ui` to GHCR in a GitHub Actions job on merge to `main`.
2. Switch Compose on the VPS from `build:` to `image: ghcr.io/<owner>/...:<tag>`.
3. Deploy step: SSH to the VPS (deploy key stored as a GitHub secret), `docker compose pull && docker compose up -d`, then run a smoke test and fail the job if `/health` or `/predict` does not respond.
4. Add the missing CI steps: flake8 on `api ui`, and a Docker build check on every PR.

### Phase 6: Model lifecycle
- Retraining happens in CI (`python -m src.train`); the quality gate blocks a weak model.
- Promote a model by committing the new `models/heart_model.joblib`, which triggers a rebuild and deploy. Tag releases so a rollback is `git checkout <tag>` plus redeploy.
- Optional later: serve MLflow on the VPS (behind auth) and load the model from the registry instead of baking it in.

## 8. Local quick start

```bash
docker compose up -d --build          # api, ui, prometheus, loki, promtail, grafana
curl localhost:7201/health
curl -X POST localhost:7201/predict -H "Content-Type: application/json" \
  -d '{"age":63,"sex":1,"cp":4,"trestbps":145,"chol":233,"fbs":1,"restecg":2,"thalach":150,"exang":0,"oldpeak":2.3,"slope":3,"ca":0,"thal":6}'
```

UI: http://localhost:7202 · Grafana: http://localhost:7205 · Prometheus: http://localhost:7203

Retrain and inspect experiments:

```bash
pip install -r requirements-dev.txt
python -m src.train
mlflow ui --backend-store-uri sqlite:///mlflow.db
pytest && flake8 src tests
```
